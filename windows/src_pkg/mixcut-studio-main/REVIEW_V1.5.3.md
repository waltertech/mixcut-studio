# V1.5.3 代码复核与自测

## 修复范围

1. 抽帧错位：关闭连续抽帧管线的自动过滤器重建，避免颜色元信息变化重置selected_n。一次解码经过split输出320px小图与960px大图，两者对应同一源帧。发布缓存前核对两种图片的数量与完整性。
2. 旧缓存迁移：缓存算法标识改为keyframes-v3-paired-30s，尚未审核的成片在启动时排队重新准备；有效新缓存不重复生成。生成串行、有取消和超时，音乐规划不增加检测工作。
3. 页面生命周期：展开状态按任务标识保存；统一处理轮询、全选和删除引起的列表重建。展开直接读图片清单；收起暂停播放，销毁悬停层。失效或移除的任务释放媒体对象。图片读取异常提供重试，清单请求30秒超时。
4. 审核成功与清理：复制归档、删除制作目录成片之前保留列表和展开状态。成片删除失败不再隐藏任务。先删除成片成功，再清理其图片，避免删除失败后失去审核预览。
5. 审核不通过：独立于普通删除记录。确认后将使用的视频路径持久排除，再删除成片、原视频及缓存；保留原音乐。失败保留可见任务与重试状态；重启后的中断清理可手动重试。贴图版本会追溯原任务，清理未归档的原成片与原视频，已独立归档的文件保留。
6. 后续任务：规划、手动替换、补救候选与分段原输入均检查排除记录；已排除输入的旧检查点也不会继续复用。缺失或不通过素材按既有补救流程替换，不能补救时保留状态并让队列继续。

## 代码复核

- 普通任务删除仍然只移除记录与预览，不删除视频或音乐；文件删除只发生在明确的审核操作中。
- 审核不通过和通过审核采用同一审核锁，避免同一任务同时归档和删除。
- 原素材删除限定在任务记录的视频目录，并验证素材身份和路径；已登记为音乐的同一文件受到保护。
- 原音乐路径不进入删除清单；实际音乐与视频共用一个文件时会明确提示先分离音频，避免违反音乐保留要求。
- 排除信息只保存路径与时间，不读文件内容、不做指纹；扫描进度使用一次读取的排除集合，避免每条素材重复访问数据库。
- 图片接口对单张图片仅检查该文件，整套完整性检查放在清单与审核入口，避免数百张图片相互重复检查。
- Windows配套源码同步公共后端、界面及测试，保留Windows专用媒体实现。

## 使用说明与范围

- 安装前等待正在渲染的任务结束，退出旧版后台，再安装新版。没有替换当前正在运行的应用或操作用户的实际文件。
- 第一次升级会为尚未审核的旧成片重建缩略图，可能需要等待；新任务正常在后台生成完图片后才开放审核。
- 审核不通过为直接删除，文件不会进入废纸篓；同一原视频被其他任务引用时，也会按用户要求删除并排除，后续渲染会尝试替换。
- 磁盘离线、权限不足、音视频共用同一文件等情况会明确报错；不承诺此类条件下能完成所有清理。
- 未进行数十条小时级任务的持续压力测试。测试文件均位于隔离临时目录，未删除用户实际素材。
