# V1.8.8 验证与实现说明

## 数据与分配

本地 state.sqlite3 新增 music_folder_success（每条成功任务的去重记录）和 music_folder_usage（文件夹成功总次数与最近使用时间）。成功状态、去重事件与累计统计在同一数据库事务提交，审核、任务列表删除不会删除这两张表。列表状态仍用于动态计算待制作占用，不新增高频后台轮询。

同批先保持文件夹尽量不重复；在同一轮候选内，优先“历史成功次数＋当前待制作数”少的文件夹，再选择更久没成功使用的，最后随机。新文件夹默认为零。失败、取消、删除释放占用；恢复重试重新占用，同条任务成功只计一次。暂停中的未完成任务继续占用。手动明确选择文件夹仍尊重用户选择。

手动生成与定时生成在分配到保存方案期间共用互斥锁，防止同时提交多批时读到相同的旧占用。随机更换文件夹参考同一份记录，排除自身占用。

启动时仅补录仍保留在数据库的成功任务，不扫描磁盘历史文档，不猜测已经清除的旧任务。旧成功任务的最近时间采用原记录更新时间近似。贴图衍生任务和独立音乐 Set 不记入普通音乐文件夹使用次数。改名、迁移路径会作为新的文件夹身份。

## 性能与兼容

不读取音频内容、不解码、不新增指纹。不在页面轮询中统计全部历史，规划时读取汇总及现有任务。成功条目保存标记，后续进度写入不会反复提交历史事件。事件表用于重试、重启去重。旧版忽略新增表，可保留旧安装包回滚；旧版期间已被清除的任务历史无法事后补齐。

规划页面显示“规划时历史成功”“已有待制作”和本组使用次数，明确是分配时快照。

## 验证

- 全部 332 项 unittest 通过（新增 14 项文件夹历史及生命周期回归）。
- 覆盖计数持久化、删除及审核自动清理后保留、失败取消释放、重试去重、启动补录、并发成功、并发生成、手动变更、最近使用排序、两类普通规划器、定时续批已有条目避免重复计数、同批尽量唯一。
- 最终安装包实际服务：连续生成三批分别选三个文件夹；实际渲染三条短视频，每个文件夹累计一次；删除任务后重启，次数保留；下批选择最早成功的文件夹；实际页面显示统计。原视频与音乐均保留。
- 独立音乐 Set 安装包验收通过：三任务同时制作、不抽帧、播放器收起暂停、审核、删除任务及原有页面导航。
- 安装包内版本 1.8.8、FFmpeg/FFprobe 检查通过。测试使用隔离临时目录，没有修改用户正在运行的后台或真实库。
- 上述短视频验收不代表新增长时间硬件压力测试；本次未更改编码和渲染算法。
