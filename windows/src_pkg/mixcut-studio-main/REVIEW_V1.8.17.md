# V1.8.17 验证记录

## 定位证据

真实V1.8.16后台日志显示：删除API -> _forget_records -> _visible_batch -> approved_record_ready -> Store.get -> sqlite3.OperationalError: database is locked。后续单条及批量删除多次返回500，约30秒一个失败周期。原实现每次Store.connection新建连接，Python RLock虽可重入，但新SQLite连接不属于外层未提交写事务；较大事务写锁/页溢出时嵌套读取自锁，较小事务也可能读到旧快照。自动跨批次prune同样会在已有写操作后再调用Store.get。

真实状态库只读PRAGMA quick_check返回ok。未修复/重建/清空真实数据库，未删除真实任务，未中断真实后台。

## 实现

Store.connection在可重入Store锁下维护每线程活动连接。嵌套调用复用连接；只由外层负责commit/rollback/close，嵌套写入随外层事务整体回滚，线程结束调用后无遗留连接。不同线程仍被现有Store锁串行保护。删除返回的可见状态整理放在事务提交后。未变更journal模式或通过增加timeout掩盖自锁；外部进程独立占锁仍应另行定位。
