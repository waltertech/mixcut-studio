# V1.5.7 代码复核与自测

## 实现

- 新方案直接预约“保存根目录／生成方案当天日期／编号-根目录名”任务目录，视频及同名文档分别写入对应目录。贴图任务同样采用独立目录。跨午夜继续使用已预约的日期目录。
- 当日不同方案共用目录编号，目录独占创建避免覆盖，编号与音乐或视频文件名无关。旧路径记录不迁移。
- 新审核入口只保存通过状态和原成片路径，使用已有文件大小、修改时间检查，不复制成片、不为新归档做整段哈希。老归档恢复路径仍保留原有完整性检查。
- 审核后清理缩略图、工作缓存及可安全删除的原视频素材；共享原片直到最后引用任务审核通过或移除才清理。原音乐不删除。
- 删除通过操作系统接口回收整个任务目录；旧共用目录只回收任务视频及同名文档。只有回收完成才移除记录，失败可重试，不降级为永久删除。
- 执行中删除先置取消标记并等待任务退出（最多10秒）；未结束时返回说明，记录及文件保留，后续可重试。并行的其他任务继续执行。
- 审核、回收与记录变更通过审核锁串行，保持任务索引在活跃执行期间稳定。批量回收中途失败时已回收文件不会恢复；记录保留，重试可继续处理剩余任务。
- 未单独通过的贴图原成片在替代版通过后回收；单独通过的原成片保留。旧审核目录选项隐藏，新增每条任务打开成品文件夹入口。
- 本地状态目录保存方案 manifest，避免日期目录中混放方案文件。
- 前端、后台、原生窗口和公共Windows源码同步到1.5.7，接口协议13，避免新版界面连接旧审核后台。

## 自测证据

- 主源码255项全量回归测试通过；另外补充共享原素材清理专项：两条原地保留任务通过后才清理原素材，两个成片保留，不执行成片哈希。
- 原地审核6项专项通过：视频inode与路径不变、无复制/哈希、重新启动仍保留、已通过目录整体回收、失败记录保留、旧共用目录仅处理对应文件、拒绝任务回收及共享素材清理。
- Windows公共源码253项回归在macOS Python上通过；未运行原生Windows安装包。Windows回收调用使用编码参数，避免路径作为命令代码解释。
- macOS arm64签名、包内版本、接口协议及捆绑工具验证通过。
- 包内后台实际渲染单文件夹与全路径模式，预生成缩略图和文档；检查日期和编号目录，审核后视频inode和原路径不变，更新曲目文档不重新渲染。
- 独立Chrome连接包内后台，确认旧审核路径设置隐藏、单条打开成品文件夹按钮存在、点击审核成功后显示保留原处；没有页面脚本错误。
- 包内实际删除已通过任务及审核不通过另一任务，系统废纸篓回收成功；原音乐全部保留。隔离测试使用Downloads中的临时目录，不改动用户任务。
- 原有迁移/复制测试明确保留为旧归档恢复兼容测试；当前产品审核API采用新保留入口。

## 限制

- 未在用户外接硬盘上进行回收或小时级渲染压力测试。系统不支持回收或权限不足时保留文件和任务供重试。
- 废纸篓仍占用磁盘空间，需要清空废纸篓才释放空间。
- 新编号以已有同格式目录最大编号为基础。删除最高编号目录后，后续方案可能复用空出的最高编号。
- 输出目录在生成方案时预约，因此先删除草稿方案也会将其空目录回收。
- 已审核任务保留可查看状态；删除这条任务也会回收成品。旧审核归档保留原路径，删除旧记录时回收对应视频和同名文档，不处理共享目录里的其他文件。
