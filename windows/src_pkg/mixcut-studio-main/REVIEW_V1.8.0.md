# V1.8.0 review 与验证

## 设计检查
原规划器仅在 duration_basis=music 时进入新的 musicled 模块；无标记旧方案继续原视频时长规则。音乐 Set 的业务代码没有修改。新页面默认直接拼接，服务端亦对新规则默认关闭静音检测。

规划期间不打开媒体、不解码、不计算内容指纹。选择按整组使用次数平衡，音乐长短不影响选择权重。单文件夹使用完整集合，缺少01/02时给出明确错误。歌曲手动顺序可以覆盖自动开头规则。

实际渲染先生成完整音轨，缓存凭文件路径、大小和纳秒级时间戳及处理参数校验；拼接期间源文件改变会报错而不发布缓存。实际音轨决定视频目标长度。原音关闭时最终AAC直接复制封装。重复分段使用硬链接复用，不复制大缓存文件；失效时重新编码。

审核继续依据实际渲染片段处理视频引用；音轨缓存位于现有任务工作目录，沿用审核清理/清理缓存流程。原音乐不删除。

## 边界与限制
- 新版方案完整保留歌曲一次；全路径模式仍受最少/最多歌曲数限制。
- 视频循环会使同一源多次出现，属于补足音乐的正常行为；素材不足时无法保证不同作品画面永不相同，页面明确提醒。
- 文件路径识别无法判断不同文件是否相同内容，按已确认的性能优先策略保留。
- 实际渲染仍必须解码音乐；这是生成音轨所需工作，规划阶段不执行。
- 缺失全部可用视频或音乐、磁盘空间不足、文件在制作中变化仍会进入明确错误/暂停状态，不伪造成功。
- 旧版无法正确渲染新版方案，回滚前应先处理新版任务。

## 验证范围
自动化回归覆盖旧功能；新增用例覆盖完整歌曲、01/02顺序、整组低重复、多源循环、替换保持音乐、直接拼接默认与真实FFmpeg成片。打包后独立状态目录验证新增模式及原模式、音乐Set并行流程。最终执行结果见随包 validation 日志。
