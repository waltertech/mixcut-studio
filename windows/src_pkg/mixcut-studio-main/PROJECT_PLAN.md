# 批量混剪工具：项目规划

日期：2026-09-21  
状态：第一版本地工具已实现，50条实机批量验收与重启续跑均通过；详见 TODO.md 与 VALIDATION.md  
第一版目标平台：当前 Mac，本地网页操作、本机处理

## 1. 产品目标

选择视频文件夹和音乐文件夹，配置剪辑方式、期望时长和数量，自动生成不同的视频方案和完整歌曲排列，批量导出成片。设定 50 条时，以通过检查的 50 条成片为完成标准。

第一版无需 Agent、模型接口或 API Key，不接入 Jev。原始视频和音乐留在本机，程序不覆盖素材。

## 2. 当前素材与已确认需求

已检查文件信息，并对每个视频抽样查看 4 个时间点；尚未完整观看、试听全部素材。

| 素材目录 | 当前内容 | 对实现的影响 |
|---|---|---|
| `哔哩哔哩/` | 4 个 TS 视频，约 23 分 05 秒；720p/30fps 与 1080p/60fps 混合，均有原音轨 | 递归扫描；混合来源导出需统一画幅、帧率；不默认按文件名判断精彩程度 |
| `去重歌曲03/` | 9 个 MP3，约 41 分 40 秒；其中两首约 24 秒、23 秒 | 按实际时长规划整首歌曲组合，不能假设每首都数分钟 |

已确认：两种剪辑模式、允许跨成片复用部分画面、自由选择期望时长、批量输出、视频方案与音乐方案均不完全相同、完整歌曲只调整选曲和顺序。

## 3. 两种剪辑模式

### A. 单源连续截取

每条成片仅使用一个源视频的一段连续区间。批次可以自动在多个源视频中分配，也可以限定一个源视频。成片内部不打乱、不拼接、不循环。

截取选项：

- 不重叠顺切：按成片实际时长顺序分配区间；数量受素材长度约束。
- 允许重叠：从不同起点生成区间，优先分散起点；显示批次内的重合程度。
- 起点最小间隔：避免只偏移一帧就当成明显不同的成片。具体默认值在样片阶段确定。

一段 10 分钟素材不重叠只能产生 3 条完整的 3 分钟片段；以 30 秒间隔移动起点则有 15 个候选，但相邻片段高度重合。

完整歌曲总时长必须小于等于所选源视频可用长度。素材不够时提示调整歌曲或切换模式，不自动循环、变速或切换模式。

### B. 多源连续片段拼接

每条成片从至少两个不同源视频取连续区间，按计划顺序连接。每段保持原始时间顺序。

- 配置每段最短、最长时长，例如 30～120 秒。
- 自动分配段长以匹配完整音乐总长，避免末尾出现极短碎片；无法满足时重新规划或报告不可行。
- 同一成片中不重复使用同一源视频的重叠区间；允许从同一源视频取多个不重叠区间。
- 可选素材分组，选择同组内拼接或跨组拼接；第一版采用手动分组。
- 默认直接切换镜头，暂不加入复杂转场。

## 4. 完整音乐与时长规则

硬规则：每首从头到尾完整播放，不截取、不变速、不默认循环、不交叉重叠。第一版不做自动首尾淡化或静音裁切。音量调整不改变歌曲内容和长度。

提供两种选曲方式：

1. 固定歌曲集合、改变顺序：每条都使用所选歌曲，每首一次，仅改变排列。
2. 从候选池选择子集、改变顺序：设置每条歌曲数量范围，选择符合期望时长的组合，再排列；单条内每首至多一次。

允许手动指定第一首或开头候选池，第一版不自动判断音乐吸引力。

成片时长等于所选完整歌曲的累计播放时长。界面允许输入期望时长与容差，或最短～最长区间。预览展示实际时长。

- 没有符合时长范围的组合时，展示最接近的候选与差值，由用户修改设置后再生成。
- 不通过截歌、变速、补静音来强行匹配目标。
- 编码后的成片允许存在帧/音频采样量化误差；验收容差与输出规格绑定。按完整解码音频规划，处理 MP3 编码延迟与尾部填充，不把容差用于删减歌曲。
- 单源模式还要检查每个音乐方案是否存在足够长的源视频。

例如固定 5 首不同歌曲，不固定首曲时有 120 种排列；固定其中一首开头时只有 24 种，无法提供 50 个不同音乐顺序。程序应在导出前说明不足。

## 5. 批次差异规则

“不完全一样”不等于完全无重复素材，更不代表平台会判定为原创。

第一版对同一批次要求：

- 任意两条的音乐有序歌曲列表不同，不能仅靠视频不同满足音乐去重。
- 任意两条的视频方案不同；方案包含素材标识、起止位置和排列顺序，时间使用统一精度。
- 同内容不同文件名应识别为相同素材，使用内容指纹而非仅比较路径。
- 起点差异、素材使用次数和区间重合程度共同影响候选优先级，不能仅靠随机数保证质量。
- 画面差异以源文件和时间区间估算，不宣称完成视觉语义去重；不同录制文件里的相同画面仍可能重复。
- 展示最高两两重合比例与素材使用次数；默认允许重合。第一版支持单源不重叠顺切，跨成片重合比例的硬阈值留作后续可选项。

重合比例建议定义：两条方案在同一源文件上实际重叠区间的累计长度，除以两条成片中较短的画面时长。单条不重复区间，避免重复计数。

优先生成完整批次计划，再开始渲染。如果无法产生目标数量，报告已找到多少方案及瓶颈；搜索达到上限时说明“未找到足够方案”，不要误报数学上绝对不可能。

跨批次去重留到后续版本；第一版保留历史方案，为后续扩展提供数据。

## 6. 产品形态与界面

第一版是双击启动的本地网页工具：浏览器负责界面，本地后台负责扫描、规划和导出。服务仅监听本机，不依赖云端。

四个主要页面：

1. 素材：选择/填写本机文件夹路径，递归扫描，显示缩略图、时长、规格、音乐试听和手动分组。
2. 设置：剪辑模式、素材范围、期望时长、数量、段长、重叠规则、选曲方式、开头歌曲和导出位置。
3. 方案预览：展示每条的实际时长、视频区间、歌曲顺序、重复统计和不可行原因；确认后开始渲染。
4. 任务与结果：完成/待处理/失败计数、当前进度、暂停、继续、重试、停止，以及成片预览和定位输出文件。

路径选择要实际验证 Mac 浏览器与后台的配合；保留绝对路径输入作为第一版可靠入口，素材不通过网页重复上传。

关闭浏览器不停止后台任务，重新打开可继续查看。退出后台、电脑关机或休眠无法保证继续运行；重新启动后从未完成条目恢复。第一版暂停按“当前成片完成后暂停”实现，中途退出则重做未完成成片，不承诺恢复到编码中的某一帧。

## 7. 实现结构（拟定，开发前检查本机依赖）

采用单个本地服务和轻量网页界面，建议 Python 后台、SQLite 保存任务状态、FFmpeg/ffprobe 处理媒体。无需引入完整时间线编辑器、消息队列集群或 Agent 框架。

处理流程：素材扫描 → 完整音乐组合 → 视频区间规划 → 批次去重/可行性检查 → 保存计划 → 排队渲染 → 校验输出 → 标记完成。

关键持久化数据：

- 素材索引：路径、类型、时长、规格、文件指纹、人工分组。
- 批次配置：模式、数量、时长条件、音乐规则、输出规格、随机种子。
- 成片计划：按顺序排列的视频区间、完整歌曲列表、预计时长、方案指纹。
- 执行状态：待处理/运行中/校验中/成功/失败/已停止，错误、尝试次数与输出位置。

导出建议默认横屏 720p/30fps、MP4；提供 1080p 选项，并说明提升分辨率不会增加源画面细节。不同尺寸采用等比适配，默认不裁掉游戏 UI。最终规格在样片预览时确认。

原音默认静音，仅播放所选音乐；用户可选择保留并调低原音。默认音量值属于产品建议，尚未经过试听确认。

默认一次渲染 1 条，先测速度、温度与磁盘占用，再决定是否开放有限并发。优先验证 Mac 硬件编码可用性，不在实测前承诺导出速度。

## 8. 批量可靠性

- 完成条件是 N 条输出通过校验，不是提交了 N 个命令。
- 输出先写临时文件，校验成功后再改为最终文件名并记录成功；不覆盖其他文件。
- 每条保留计划，失败重试使用原计划；如需换方案则重新通过去重检查。
- 暂定每条最多自动重试 2 次；损坏素材、磁盘不足等持续问题暂停并提示，不无限重试。
- 后台重启核对数据库和实际文件，防止已成功但未记账的成片重复导出。
- 导出前检查路径可写、素材存在、基础可解码性和预计磁盘空间；空间预估明确标为估计值。
- 输出校验包括文件可读、音视频流、时长、完整解码检查、计划中整首歌曲的完整使用记录。文件可解码不等于内容精彩，仍需人工样片复核。
- 每批保存配置、成片清单及错误记录，可定位到源视频起止时间与音乐顺序。

## 9. 开发阶段与完成标准

| 阶段 | 交付 | 完成标准 |
|---|---|---|
| M1 素材与规划 | 素材扫描、两种模式、完整音乐组合、批次方案 | 当前 4 视频/9 音乐正确识别；不可能配置提前报告；方案可复现 |
| M2 最小导出闭环 | 单条渲染与校验 | 两种模式各产出至少 1 条可观看样片；歌曲完整、时长符合方案 |
| M3 批量执行 | 50 条队列、去重、失败重试、断点续跑 | 可行配置下完成 50 条有效成片；重启后不重复导出成功项 |
| M4 本地网页 | 四个页面、启动入口、试听预览、进度 | 能从选文件夹到查看成片走通；无需命令行日常操作或 API Key |
| M5 交付整理 | 操作说明、启动/停止说明、验收记录 | 使用当前素材完成全流程验证，明确速度、空间与质量限制 |

M3 的 50 条压力验证安排在小规模样片通过之后，避免先生成大量不符合预期的文件。

## 10. 第一版之外

- Jev、视频理解模型、自动精彩片段识别和音乐钩子评分。
- 自由拖拽多轨时间线、字幕识别、复杂转场和模板特效。
- 自动去除画面内主播头像、文字、水印等已有元素。
- Windows 安装包、云端部署、账号系统和多人协作。
- 全局跨批次去重、视觉语义相似度、自动游戏分类。
- 桌面安装包：本地网页稳定后，再评估封装 Mac 应用及依赖打包。

## 11. 第一版验收场景

1. 递归扫描当前素材，不把 ZIP、隐藏文件或既有输出当作新素材。
2. 单源模式：完整音乐小于源视频长度时成功；大于时清楚报错，不截歌或循环画面。
3. 多源模式：至少两种视频来源，段长符合设置，总画面时长覆盖完整音乐。
4. 固定 5 首、固定第一首、要求 50 个不同顺序时，提前提示最多 24 种。
5. 基于当前素材选择可行参数，成功导出 50 条；音乐列表和视频方案分别唯一。
6. 任取输出可回查源片段和完整音乐顺序；试听确认接缝没有意外截断。
7. 关闭网页、重开网页、退出后台并重启分别验证，已完成文件不丢失、不重复生成。
8. 损坏素材与空间不足能显示可操作错误；失败不能被计入成功数。
