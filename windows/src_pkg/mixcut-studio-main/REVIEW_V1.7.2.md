# V1.7.2 修复审查与测试

2026-10-11

只读检查本地实际任务数据：17 条任务中，16 条保存的并行数量为 3。说明界面选择已在导入时保存，单任务执行并非所有任务都被保存为并行 1。

代码定位：旧前端逐条启动选中任务；后台 run_next 只快照当时队列并执行固定的一组，第一条入队即可启动一人组，后来入队的任务无法补入，形成截图中的等待现象。另有导入后调整并行选项未传到开始接口的问题。

本次修复增加批量启动接口，在共享锁中验证并入队；启动时保存当前并行上限；运行池等待单条完成并持续补入空位。最多 4 个线程，按当前上限派发；若运行中降低上限，已有任务正常完成，之后按新上限补入，不强行中断。单条、批量开始采用同一当前设置入口。旧任务数据兼容，无需重新导入。
