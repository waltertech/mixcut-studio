# V1.6.0 审查与测试

## 确认的原因

单文件夹分配函数过去每轮直接打乱全部歌曲，没有01/02开头规则。前端歌曲排序保存后调用renderPlan重建DOM，details节点没有保留open状态，因此自动收起。

## 修复

初次随机时根据已扫描文件路径的文件名开头识别01、02，依次固定前两首，剩余歌曲洗牌；后续循环继续洗牌全部歌曲。初次生成、刷新整条音乐、更换文件夹使用同一个分配函数。前两位单曲随机替换受保护，拖动和箭头排序仍完全允许人工修改。全局模式不变。

支持01 歌名、01-歌名、01歌名等格式，010和020不作为01/02。重复编号按路径稳定选择一个，缺少编号显示提示且保留旧文件夹可用性。不会把所有任务的前两首强制锁定到同一首全局歌曲，仍只取当前选中文件夹。

展开状态按任务标识保存；重建前同步实际open状态，重建后恢复。已移除节点的延迟toggle事件不能覆盖新状态。收起的列表继续按需生成内容，不增加媒体解码、指纹或文件内容读取。

## 验证

- 完整主源码回归266项通过，Windows共享源码264项通过。
- 100个随机种子验证前两首固定、其余歌曲顺序变化、后续循环不固定01/02，以及每轮歌曲完整。
- 验证缺少编号、重复编号、010/020边界、单曲及双曲文件夹。
- 后端验证初次规划、重新排列、更换文件夹、手动排序，以及前两位单曲随机替换保护。
- 实际安装包浏览器测试箭头点击、通过DataTransfer触发拖放事件处理、重新排列、手动收起后再次刷新；展开状态正确保持，人工顺序可保存，无页面错误。未将拖放事件测试等同于原生WebKit窗口鼠标拖动的自动化验证。
- 安装包实际渲染三条短视频，并回归原地审核、原视频移至系统废纸篓、删除记录保留文件和原音乐不动。
- JavaScript语法和差异空白检查通过；安装包构建、签名与接口版本校验通过。接口协议16避免误连旧后台。

## 边界

编号01/02的对应歌曲必须存在且可用才能完整满足自动开头规则；缺失时方案提示。损坏音乐仍沿用既有的渲染恢复逻辑。展开状态在本次页面会话内保留，关闭应用后不单独持久化。未进行外接硬盘长时间压力测试。Windows同步源码，未制作Windows安装包。
