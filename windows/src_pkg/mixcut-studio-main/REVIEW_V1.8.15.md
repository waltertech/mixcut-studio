# V1.8.15 验证记录

## 原因与规则

扫描本身递归读取了所有音乐；旧 foldermusic.groups 固定取相对于扫描根目录的第一段目录，将分类目录下多个 Set 合并。现在按每首有效音乐的直接父目录归组，剔除含更深音乐目录的祖先组，只保留末级音乐组。封面等不含有效音频的子目录不影响歌单。

支持选择高层分类、低层分类或直接选择歌单。完整路径是身份，分类下的同名 Set 不合并。已有歌单的成功使用历史仍按原完整路径保留；旧分类目录聚合的历史不冒充分配给各个子歌单。

单文件夹规划、手动更换文件夹、重新排列、音乐替换等共用同一函数；固定集合、全路径随机和独立音乐 Set 交接不改。现有批次不重写，旧错误合并方案须重新生成。

## 性能

仅使用已有扫描元数据，无额外目录遍历、音频解码或指纹读取；工作量随歌曲数与目录深度线性增长。
只读打开真实数据库的扫描记录：2165 首音乐分为 440 个独立末级歌单，最大 30 首/组；分组约 0.0397 秒。未改动真实库、素材或任务。

## 验证

- 381 项 unittest 全部通过。覆盖 10 层分类、同名 Set、父目录散放音乐、扫描根目录本身是 Set、不同选择层级结果一致、分组无目录读取，以及规划先用不同 Set、01/02 开头、两轮音乐时长和视频长度匹配。
- macOS 冻结安装包版本为 1.8.15；构建内置服务版本与 FFmpeg 可用性检查通过。
- 安装包独立临时库与真实浏览器验收：12 个真实音频跨 4 个歌单（含 10 层路径），设置页显示 4 个独立音乐文件夹；实际点击生成方案得到 4 条独立任务，手动切换下拉框仅列 4 个歌单。每条 3 首、2 轮共 6 秒，不合并分类目录。
- 通过实际扫描 API 将音乐路径改为某个末级歌单本身后，规划仍成功且只使用该歌单。
- 本次安装包验收不重新渲染成片，不操作真实后台。Windows 同步源码，未构建 Windows 安装包。
